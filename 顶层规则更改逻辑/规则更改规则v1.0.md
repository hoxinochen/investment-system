Authority Artifact Release Rule v1.0

STATUS: DRAFT  
VERSION: 1.0

1. 定位

本规则定义投资研究系统中 Authority、Schema、SPEC、Prompt、Handoff 等制品的生命周期管理方式。

本规则属于治理层（Governance Layer），不参与晨报、月报的日常研究判断。

2. 适用范围

适用于以下 Artifact：

- Authority（权威规则）
- Schema（数据结构协议）
- SPEC（执行规范）
- Prompt（执行行为定义）
- Handoff（跨周期状态传递协议）
- Governance Rule（治理规则）

3. Artifact 生命周期

状态：

DRAFT → REVIEW → FROZEN → SUPERSEDED

说明：

- DRAFT：草稿，可修改或由人工删除。
- FROZEN：正式生效版本，不允许静默修改。
- SUPERSEDED：被新版本替代，但保留历史关系。

4. 新版本生成规则

任何 Authority / Schema / SPEC / Prompt 升级必须生成完整可独立消费版本。

禁止：

- 仅生成 Changelog 作为运行版本；
- 仅描述相比旧版本变化，而不提供完整正文；
- 假设下游会自动读取旧版本补全缺失内容。

Changelog 只能作为附录存在。

5. 版本迁移要求

新版本必须声明：

- VERSION
- STATUS
- SUPERSEDES
- EFFECTIVE_FROM（如适用）
- Migration Notes

迁移必须基于当前有效版本，而不是基于记忆或摘要重新生成。

6. 读取触发条件

当用户请求涉及以下行为时，必须读取本规则：

对象：

- Authority
- Schema
- SPEC
- Prompt
- Handoff
- Governance Rule

行为：

- 创建
- 修改
- 升级
- 迁移
- 冻结
- 废弃
- 替代
- 发布

7. 权限边界

AI可以：

- 提出升级方案；
- 生成 Draft；
- 生成 Migration Notes。

AI不得：

- 自行冻结版本；
- 删除 Frozen Artifact；
- 静默修改历史版本；
- 将 Draft 当作运行版本。

8. 设计原则

Memory ≠ Authority

Conversation ≠ State

Rule ≠ Trigger

Artifact 存在不代表自动生效，必须通过明确触发路径调用。
