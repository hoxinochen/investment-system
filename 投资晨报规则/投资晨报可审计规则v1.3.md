版本迁移说明

本版本基于 Audit Ledger v1.2 全量继承。  
v1.2 中关于 WORM、事件类型、Research Logic Snapshot、Current State Reconstruction 等规则保持有效。

本次调整 1. 强化与 Handoff 的状态接口

Daily Ledger 作为 Event Stream（事件流），不保存完整研究报告。

Current Research State:  
Latest Valid Handoff  
+  
Handoff VALID_FROM 后的有效 Daily Events。

2. Research Priority Event 边界与统一动作

RESEARCH_PRIORITY_CHANGED 仅用于真正改变未来研究注意力分配的事件。

该事件与 Handoff 使用同一组 `topic_key` 和有限动作：  
`ADD / RAISE / MAINTAIN / LOWER / EVENT_TRIGGER_ONLY / REFOCUS / DROP`。

正式事件至少包含：

- `EVENT: RESEARCH_PRIORITY_CHANGED`
- `ID`
- `date`
- `topic_key`
- `action`
- `reason`
- `review_window`（`DROP` 可按退出条件使用 `reentry_condition`）

按动作需要补充 `focus_on`、`stop_researching`、`trigger_condition` 或 `reentry_condition`。  
同一 `topic_key` 的更晚 Daily Event 覆盖 Handoff 在 `VALID_FROM` 时点的初始 Directive，但不得修改旧 Handoff。

v1.2 中的旧动作按以下方式兼容读取：

- `REMOVE` 视为 `DROP`；
- `REBALANCE` 不作为新事件动作；新记录必须拆成一个或多个带 `topic_key` 的明确动作。

以下不产生事件：

- 普通新闻；
- 单日行情变化；
- 研究漂移检查但未改变注意力；
- 临时关注事件。

3. Snapshot 约束

Research Logic Snapshot 只保存当时足以重建判断逻辑的信息。

禁止：

- 写入事后证据；
- 复制晨报全文；
- 用后续结论修改原判断。

4. 版本治理

历史 Ledger 永久冻结。  
任何判断变化必须创建新 Event，不允许修改旧记录。

设计原则

Reality Change -> Baseline Event  
Forecast Change -> Forecast Event  
Hypothesis Change -> Hypothesis Event  
Research Method Change -> Method Event  
Research Attention Change -> Research Priority Event

Daily Ledger 是研究状态事件流，不是新闻数据库。
